# loading-ux-tester

## 1. 概要

このプロジェクトは、Webサイトのローディング時間と、その間に表示されるエフェクトが、ユーザーの**体感時間**や**UX (ユーザーエクスペリエンス)**にどのような影響を与えるかを、開発者自身が直感的に理解・体感するためのインタラクティブなWebツールです。

Webパフォーマンスの重要性をデータ（離脱率など）だけでなく、感覚として理解することを目的としています。

## 2. 目的

-   **仮説の検証:** 「ローディング時間が同じでも、気の利いたエフェクトがある方が、体感的な待ち時間は短くなる」という仮説（仮説A）を体験的に検証する。
-   **開発者の意識向上:** Webエンジニアがパフォーマンス改善の重要性を当事者として認識し、ユーザー体験への配慮を促す。
-   **モダン技術の実践:** モダンなフロントエンド技術（Vue 3, Tailwind CSS）の学習と実践の場とする。

## 3. 機能仕様

### 3.1. 画面構成

-   **メインエリア:** 画面中央に、アクションの起点となる大きな「ローディング開始」ボタンを配置。
-   **オプションエリア:** 画面下部に、ローディングの条件を設定するためのUIを配置。
    -   **時間設定スライダー:** ローディング時間を0秒から10秒の範囲で直感的に設定できる。
    -   **エフェクト選択:** 試したいローディングエフェクトをボタン形式で選択できる。

### 3.2. インタラクション

1.  **動的なボタン変化:**
    -   時間設定スライダーの値に応じて、「ローディング開始」ボタンの色とテキストラベルがリアルタイムで3段階に変化する。
    -   この変化は、実際のユーザー離脱リスクに基づいている。
        -   **0〜2.5秒（緑）:** `ローディング開始 (快適)`
        -   **2.6〜4.0秒（黄）:** `ローディング開始 (許容範囲)`
        -   **4.1秒以上（赤）:** `ローディング開始 (離脱リスク高)`

2.  **ローディング体験:**
    -   「ローディング開始」ボタンを押すと、画面全体が半透明のオーバーレイで覆われ、選択したローディングエフェクトが表示される（パターン1）。
    -   これにより、ユーザーは体験に集中できる。

3.  **結果のフィードバック:**
    -   設定した時間が経過するとオーバーレイが消え、画面中央に「結果のサマリーカード」が一時的に表示される。
    -   カードには、体験した「待ち時間」と「エフェクトの種類」が明記される。
    -   このカードは数秒後、またはクリック時に自動で消え、スムーズに次の試行に移れる。

### 3.3. ローディングエフェクトの種類

初期実装として、以下の4種類を比較・体験できるようにする。

1.  **何も表示しない（基準）**
2.  **グルグルするアニメーション（スピナー）**
3.  **プログレスバー**
4.  **偉人の名言を表示**

## 4. 技術スタック

-   **フレームワーク:** [Vue 3](https://vuejs.org/) (Viteを使用)
    -   理由: モダンで直感的なAPIを持つ人気の高いフレームワーク。Composition APIによる柔軟なコンポーネント設計が可能。
-   **CSS:** [Tailwind CSS](https://tailwindcss.com/)
    -   理由: ユーティリティファーストによる効率的なスタイリング。
-   **ホスティング:** [Netlify](https://www.netlify.com/)
    -   理由: Jamstackアーキテクチャとの親和性が高く、CI/CDが容易。

## 5. 開発の進め方

1.  Viteを使ってVue 3 + Tailwind CSSのプロジェクトをセットアップする。
2.  基本的な画面レイアウト（ボタン、スライダー、エフェクト選択）を実装する。
3.  スライダーと連動したボタンの動的な変化を実装する。
4.  各ローディングエフェクトのコンポーネントを作成する。
5.  ボタンクリック時のオーバーレイ表示と、完了後の結果サマリー表示を実装する。
6.  Netlifyにデプロイし、公開する。
